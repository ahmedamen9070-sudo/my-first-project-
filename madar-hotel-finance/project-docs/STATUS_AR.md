# حالة المشروع — 26 أكتوبر 2026

## المتفق عليه

نظام مالي للفنادق لمستخدم واحد أولًا، بكروت دون قائمة جانبية، وأيقونات مرسومة، وداش بورد قابل لفتح التفاصيل. الإدخال في نوافذ مستقلة بخيارات مرئية دون قوائم منسدلة، وتعبئة تلقائية للبيانات المرتبطة وأكواد ومراكز تكلفة تلقائية. مستندات للطباعة بتوقيعات، وقيود وترحيل وفق دورة كل عملية، وذكاء اصطناعي مساعد لاحقًا. فاتورة المورد مستقلة عن الاستلام وقد تكون مصروفًا أو خدمة مباشرة.

## منفذ ومجرب

النموذج البصري prototype محفوظ كمرجع. التطبيق الفعلي في app يتضمن:

- إضافة الموردين وأكوادهم وبياناتهم، وإضافة بنود المصروف أو الخدمة بوحدة وسعر وقسم افتراضي، وإضافة قسم بكود ومركز تكلفة تلقائي.
- اختيار المورد والبند في فاتورة مستقلة؛ تعبئة الوحدة والسعر والقسم وربط مركز التكلفة، مع اختيار مصروف أو خدمة.
- حفظ الفاتورة في SQLite بكود تلقائي، وإعادة فتحها وتعديلها والبحث عنها وإلغاء المسودة مع سجل أثرها.
- منع تكرار مرجع فاتورة المورد، وإعادة إرسال الحفظ دون إنشاء مستند ثان، وكشف تعارض التعديل من نافذتين. حسابات على الخادم باستخدام Decimal وتقريب نصف لأعلى.
- طباعة المستند المحفوظ بخانات توقيع، ومنع طباعة تعديلات غير محفوظة. نسخ احتياطي محلي مع فحص سلامة SQLite وسجل تغييرات.
- داش بورد بأعداد الموردين والبنود والمسودات ومجموعها الفعلي؛ ليس بإيرادات وأرباح وهمية.

نجح اختبار API مركب على قاعدة مؤقتة، بما فيه إعادة تشغيل الخادم وفحص النسخة الاحتياطية، وفحص المتصفح لإنشاء المورد والخدمة والفاتورة وحفظها وفتحها وتعديلها والطباعة وعرض الهاتف. بيانات الاختبار منفصلة عن قاعدة المستخدم. مشغل Windows مرفق لكن لم يجرّب على Windows فعليًا.

## التشغيل والتجربة

نسخة سطح مكتب: run.py يفتح نافذة pywebview أصلية مستقلة دون متصفح خارجي. Windows: START_WINDOWS.bat يجهز البيئة ويثبت متطلبات النافذة مرة واحدة؛ Python 3.10+ وEdge WebView2 مطلوبان. Linux: متطلبات Qt موثقة في app/README_AR.md. الحزمة AM-Accounting-Hotel-Desktop.zip دون بيانات المستخدم، وليست EXE مستقلًا. تم اختبار النافذة والتنقل والطباعة إلى PDF على Linux/Qt؛ Windows وmacOS لم يختبرا على أجهزة فعلية.

## لم ينفذ بعد

اعتماد الفاتورة والقيود والترحيل والأرصدة والسداد والتسويات والإقفالات، وباقي دورات الموديولات ونماذجها والتقارير المالية والذكاء الاصطناعي الحقيقي. هذه نسخة تطوير أولى وليست نظامًا ماليًا إنتاجيًا كاملًا.

## المطلوب للاستمرار المحاسبي

الدولة والعملة والضرائب وحسابات المصروفات والخدمات وتوقيت الاعتماد والترحيل. هذه لم تحسم؛ النسخة الحالية تحفظ المسودات دون عملة مفترضة أو ضريبة أو أثر مالي أو حركة مخزون. لا تنشر نسخة الخادم المحلي على الإنترنت كمنظومة إنتاج.

## اسم البرنامج المعتمد

الاسم الذي حدده المستخدم: **A&M**، والنص الكامل: **Accounting Hotel for Audit &Control**. يستخدم في الواجهة والمستندات وتعليمات التشغيل. مسارات المشروع القديمة واسم قاعدة البيانات متروكة للتوافق وحماية البيانات وليست اسمًا للمنتج.

## تحديث الشكل والتنقل

الرئيسية بصورة محلية تصورية لفندق فاخر واسم «نيو بانوراما رمسيس». الصورة مولدة وليست صورة الفندق الفعلية. الموردون كارت واحد يحتوي الملفات والبنود والفواتير بتبويبات داخلية؛ أزيل كارت الفواتير المستقل. بقيت الأكواد والربط والحفظ وفتح التفاصيل دون تغيير. أعيد اختبار دورة الموردين والواجهة على عرض الهاتف ونافذة سطح المكتب والطباعة.

## آخر تحديث بصري طبقًا للصور المرجعية

الرئيسية أصبحت كحلية داكنة بحدود ذهبية وكروت أرقام فعلية وصورة فندق رأسية تصورية وأطلس 20 أيقونة مجسمة محليًا. نوافذ الإدخال فاتحة وتحتفظ بوظائف الموردين الحالية، مع كروت مصروف/خدمة وأزرار حفظ وطباعة وإغلاق ثابتة. تم فصل مرجع الشكل عن دورات الخزينة غير المنفذة بموافقة المستخدم. نجح فحص المظهر والبيانات والتحديث والحقول والاختيار وEscape والموبايل بالإضافة إلى فحص API ونافذة Qt والطباعة.

## تبسيط الموردين قبل بدء ضبط المحاسبة

بناء على ملاحظة المستخدم: أزيل «الموردون» من التنقل بجوار «الرئيسية»، ووحّد مؤشرا «ملفات الموردين» و«بنود الموردين» في مؤشر «الموردون». أزيل تبويب البنود المستقل؛ يعرض ملف كل مورد بنوده المحفوظة وفواتيره مع إضافة بند مباشرة للمورد المحدد. البيانات والعلاقات في القاعدة محفوظة كما هي، ولم يتم دمج كيانات المورد والبند أو حذف سجلات. نجح اختبار الإضافة من الملف وحفظ ملكية البند والقسم والسعر وإعادة عرضه مع البنود القديمة، إلى جانب دورة الفاتورة وحماية التعديلات وعرض الهاتف. لا قيود أو ترحيل جديد في هذا التعديل.
